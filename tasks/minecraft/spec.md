# ТЗ: конечная voxel-песочница

**Цель:** показать создание и редактирование маленького блочного мира через текущий API raylibos.
**Архитектура:** сетка блоков и правила взаимодействия в OneScript, кубы через `DrawCube`, процедурные материалы и постоянный солнечный свет в GLSL.
**Стек:** .NET 6, OneScript, raylib-cs 6.0.0 из `src/raylibos/raylibos.csproj`; OpenGL с GLSL 330. Поставляемую нативную библиотеку и зависимости не обновлять.

## 1. Обязательная первая версия

| Подсистема | Требование |
|---|---|
| Мир | Одна сетка **16×16×8**: X/Z по 16, Y по 8; одинаковая при каждом запуске |
| Типы | `0` — воздух, `1` — земля, `2` — вода, `3` — древесина |
| Сцена | Основание, небольшой холм, пруд и два условных дерева из древесных кубов |
| Камера | Только первое лицо; мышь управляет взглядом, игрок летает |
| Взаимодействие | Удалить выбранный блок, поставить выбранный тип на соседнюю грань |
| Досягаемость | 5 мировых единиц от позиции камеры до точки входа луча в блок |
| Освещение | Постоянный направленный свет и фоновая подсветка; без теней |
| Материалы | Процедурная детализация земли/древесины; анимированный рисунок воды |
| Вода | **Непрозрачная**, не течёт; геометрия куба остаётся неподвижной |
| Интерфейс | Центральный прицел, рамка цели, выбранный тип, подсказки и FPS |
| Завершение | Освободить захват мыши и шейдеры, закрыть окно |

Древесные блоки изображают стволы и ветви; отдельного типа «листва» и дополнительных материалов в первой версии нет. Вода выбирается и редактируется наравне с землёй и древесиной. Блоки выдаются без ограничений и не попадают в инвентарь после удаления.

## 2. Что не входит

- Бесконечная/случайная генерация, чанки, меши чанков, сохранение/загрузка мира.
- Гравитация, прыжки, столкновения при полёте, плавание, дыхание под водой.
- Инвентарь, крафт, здоровье, инструменты, время разрушения, мобы, звук.
- Прозрачная вода, отражение всей сцены, физика жидкостей, деформация геометрии волн.
- Смена дня/ночи, динамические тени, ambient occlusion, погодная система.
- Текстурный атлас, ассеты/название/интерфейс оригинального Minecraft.
- Третье лицо, геймпад, мобильный ввод, новые методы публичного API.

## 3. Управление и камера

| Ввод | Действие |
|---|---|
| Мышь | Поворот камеры, когда курсор захвачен |
| W / S | Вперёд/назад в горизонтальной плоскости |
| A / D | Влево/вправо в горизонтальной плоскости |
| Пробел / левый Ctrl | Вверх/вниз |
| ЛКМ | Удалить один блок при нажатии |
| ПКМ | Поставить один блок при нажатии |
| 1 / 2 / 3 | Земля / вода / древесина |
| Tab | Освободить/захватить курсор; при свободном курсоре движение и редактирование выключены |
| Esc или кнопка закрытия | Завершить демо |

- Скорость полёта — 4 единицы/с; диагональный ввод нормализуется, включая движение вверх/вниз.
- Перемещение использует `dt = min(GetFrameTime(), 0.05)`. Ограничение предотвращает большой скачок после паузы; скорость не привязана к количеству кадров.
- Чувствительность обзора — 0.0025 радиана на единицу `GetMouseDelta`; мышь не умножается на `dt`.
- Наклон ограничен ±85°; горизонтальный угол оборачивается в диапазон ±π. Проекция перспективная, FOV 70°.
- Начальная позиция `(8, 6, 14)`, взгляд в сторону `-Z` с наклоном вниз на 20°; полёт не ограничен границами мира.
- При потере фокуса освобождать курсор и выключать ввод. Возврат фокуса не захватывает его автоматически; Tab включает управление. Первый mouse delta после захвата пропускать, чтобы взгляд не прыгал.
- Можно пролетать сквозь блоки; это намеренный noclip-режим. Если камера внутри непустой ячейки, редактирование и рамка цели выключены до выхода из неё.
- Редактирование вызывается через `КнопкаМышиНажата` (`IsMouseButtonPressed`), не через проверку удержания. При двух одновременных нажатиях приоритет у удаления; установка в том же кадре не выполняется.

## 4. Сетка и начальный мир

Ячейка `(x,y,z)` занимает `[x,x+1) × [y,y+1) × [z,z+1)`. Куб рисуется в центре `(x+0.5,y+0.5,z+0.5)` размером `1×1×1`. Валидны X/Z `0..15`, Y `0..7`; за границей читается воздух, запись отвергается.

Хранение — плоский `Массив` из 2048 ID. Индекс:

```text
index = x + 16 * (z + 16 * y)
```

Начальная сцена задаётся детерминированными операциями, а не шумом:

1. Земля: весь слой Y=0 и весь слой Y=1.
2. Холм: земля X=2..5, Z=3..6, Y=2; затем X=3..4, Z=4..5, Y=3.
3. Пруд: вода заменяет землю в X=9..12, Z=4..7, Y=1. Дно Y=0 остаётся землёй.
4. Деревья: стволы `(3,y,11)` и `(12,y,11)` для Y=2..5. Для каждого дерева добавить ветви `(x-1,5,11)`, `(x+1,5,11)`, `(x,5,10)`, `(x,6,11)`.

Ожидаемые количества: земля — **516**, вода — **16**, древесина — **16**, воздух — **1500**. Эти числа — контрольный тест начальной сцены, а не требование рисовать все клетки каждый кадр. Нижний слой тоже можно разрушать; «бедрока» нет. После перезапуска исходная сцена восстанавливается.

## 5. Прицеливание и редактирование

- Центральный луч берётся из собственных числовых позиции/направления игрока; он совпадает с направлением `Target - Position` камеры. Нельзя использовать фактическую позицию системного курсора вместо центра взгляда.
- Поиск — DDA: последовательный обход клеток сетки с точными пересечениями границ, а не проверка всех кубов или шаг по лучу с фиксированным интервалом.
- Выбор возвращает ячейку, нормаль входной грани и расстояние; выбирается первый непустой блок, включая воду. Земля за водой недоступна, пока вода не удалена.
- Удаление заменяет ID цели на воздух. Установка записывает выбранный ID в `цель + нормаль`, только если ячейка внутри мира и пуста.
- Запрещено ставить блок, пересекающий куб безопасности вокруг камеры с полуразмером 0.2. Это запрет размещения рядом с глазами, а не система коллизий движения.
- Если цели нет, она дальше пяти единиц, соседняя клетка занята или вне мира, действие не меняет сетку. Границы мира нельзя расширить установкой.
- Рамка цели рисуется через `DrawCubeWires` размером 1.005, чтобы не совпадать с поверхностью блока. При недопустимой установке рамка может оставаться на выбранной цели; HUD показывает причину отказа.

## 6. Рисование и освещение

- Размер начального окна 960×540, разрешено изменение размера, целевой лимит 60 FPS. Центр HUD вычисляется из текущих логических размеров окна, не из жёстко заданного разрешения.
- Земля и древесина непрозрачны; вода тоже непрозрачна, без дополнительных проходов альфа-смешивания. Сначала мир, затем рамка без материального шейдера, затем HUD в 2D.
- Скрывать **целые кубы**, окружённые шестью непустыми клетками; за границей сетки сосед считается воздухом. Это не удаление отдельных внутренних граней и не построение меша.
- Кэш списка рисуемых блоков перестраивается после изменения мира, не каждый кадр. Обёртки `Vector3` центров и цвета кэшируются; расстояние отсечения — 24 единицы от камеры до центра куба.
- Материалы: коричневая земля с мелкой зернистостью, древесина с полосами волокон, синяя/бирюзовая вода с движущимися бликами. Земля и древесина не меняют рисунок при движении камеры.
- Направление к источнику света `normalize(0.4, 1.0, 0.3)`; базовое освещение `0.35 + 0.65 * max(dot(normal, light), 0)`. Верх и боковые грани различаются по яркости; блоки не отбрасывают тени.
- Для каждого типа — отдельная группа вызовов с завершением шейдерного режима между группами. Не менять uniform типа материала посреди накопленного render batch без его сброса.
- Перед реализацией освещения подтвердить на одном кубе корректные нормали/мировые координаты в пути `DrawCube`. Если `vertexNormal` недоступен, вычислять нормаль из производных мировой позиции в GLSL. Успешная компиляция сама по себе не подтверждает правильный свет.
- Водный эффект в 3D писать отдельно: существующий `resources/shaders/water.fs` использует экранные координаты, его нельзя просто наложить на кубы. Анимация — рисунок/освещение граней без изменения их геометрии, чтобы между блоками не возникали щели.

## 7. Производительность и приёмка

60 FPS — цель, **не подтверждённое свойство**. Измерить при 960×540 после 5 секунд прогрева, отдельно в начальном мире и после 100 успешных изменений блоков. Каждый замер длится 30 секунд; фиксируются ОС/GPU, версия OneScript, фактический render size, среднее и 95-й перцентиль времени кадра, количество рисуемых кубов.

Ориентир для приёмки на согласованной машине: среднее не ниже 30 FPS (среднее время кадра ≤33.3 мс), 95-й перцентиль ≤50 мс, без регулярных пауз >100 мс. На более слабой машине отклонение документируется; не скрывать его лимитом `SetTargetFPS`. Проверить также худший профиль сетки — шахматное заполнение без полностью окружённых кубов; это диагностический стресс-тест, не обещание целевой скорости при любой конфигурации.

Версия готова, когда:

1. Детерминированные проверки сетки, луча, камеры и редактирования проходят без GUI/DLL.
2. Окно показывает сцену с различимыми материалами и направленным освещением.
3. Работают полёт, мышь, выбор типа, установка/удаление, ограничения дальности и границ.
4. Пройдён [ручной чеклист](manual-checklist.md), либо непроверенные пункты явно отмечены.
5. Есть результаты замеров и документированная команда запуска; ресурсы освобождаются при закрытии и ошибке шейдера.
6. Публичный API и зависимости не изменились, существующие демо не сломаны.
