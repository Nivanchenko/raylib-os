# План реализации voxel-технодемо

**Цель:** реализовать [ТЗ](spec.md) небольшими проверяемыми этапами, без расширения публичного API.
**Архитектура:** независимая от raylib логика сетки, игрока и редактирования; адаптер ввода/окна и рендер в OneScript; один GLSL-путь с тремя материальными группами.
**Стек:** OneScript, текущая .NET 6-компонента raylibos, GLSL 330.

Для исполнения плана сначала прочитать [handoff.md](handoff.md). На каждом этапе использовать соответствующий раздел [implementation-notes.md](implementation-notes.md) и строки [test-cases.md](test-cases.md), а не придумывать интерфейсы заново.

## Общие ограничения

- Мир 16×16×8, ID 0/1/2/3, досягаемость 5, полёт без физики, непрозрачная вода.
- Не изменять `src/raylibos/Raylibos.cs`, `.csproj`, `dependency/` и существующее демо воды.
- Сначала тест, его ожидаемое падение, минимальная реализация, повторная проверка. Каждый этап заканчивается проверяемым результатом, а не обещанием следующего этапа.
- Новые пути ниже — **планируемые**, не существующие команды/файлы. Их запускать только после создания на соответствующем этапе.
- Перед этапом смотреть `git status`/diff и сохранять чужие изменения. Коммиты — отдельными порциями только по согласованию с пользователем.

## Контракты логики

Не передавать `IValue`/COMWrapper в вычислительные модули. Векторы логики — `Структура("X,Y,Z", X, Y, Z)` с числовыми полями; конвертация в `НовыйВектор3` только в рендере/создании камеры.

- `Новый Мир()` — исходная сцена; `Очистить()` — воздух во всех клетках для тестов.
- `Мир.Версия` — экспортируемый числовой счётчик изменений. Успешная запись увеличивает его; отказ не изменяет. `Очистить()` увеличивает один раз, только если что-то изменилось.
- `Мир.ВГраницах(X,Y,Z)` → Булево; `ПолучитьБлок(X,Y,Z)` → ID (за границей 0).
- `Мир.УстановитьБлок(X,Y,Z,Тип)` → Булево: ложь для нецелых/внешних координат, ID вне 0..3 или отсутствия изменения. Успешная запись помечает кэш грязным.
- `Мир.ОткрытыеБлоки()` → Массив структур `X,Y,Z,Тип`; читатель не изменяет элементы. Пересчёт только при грязном кэше.
- `Новый Игрок(X=8,Y=6,Z=14,Yaw=0,Pitch=-0.349065850398866)` — старт из ТЗ; необязательные аргументы позволяют задать состояние в тестах. `Позиция()` и `Направление()` → структуры `X,Y,Z`.
- `Игрок.Повернуть(DeltaX,DeltaY)`; `Игрок.Переместить(Вперёд,Вправо,Вверх,Dt)` — числовые оси -1..1, независимые от raylib.
- `ВоксельныйЛуч.Трассировать(Мир,Начало,Направление,Дальность=5)` → структура `Попадание,X,Y,Z,NX,NY,NZ,Расстояние`. При промахе `Попадание=Ложь`, остальные поля 0. Имя `Найти` зарезервировано OneScript.
- `Редактирование.Удалить(Мир,Выбор)` и `Редактирование.Поставить(Мир,Выбор,Тип,ПозицияИгрока)` → структура `Изменено,Причина`. Причины: `ok`, `no-hit`, `bounds`, `occupied`, `near-camera`, `invalid-type`, `invalid-hit`. `Выбор` — структура результата луча, её поле `Попадание` — Булево; не путать структуру и флаг.
- `Отрисовка.Инициализировать(Рейлиб,Мир)`, `Синхронизировать(Рейлиб,Мир)`, `Нарисовать(Рейлиб,Мир,ПозицияИгрока,Время)`, `Завершить(Рейлиб)` — адаптер; `Нарисовать` возвращает количество реально нарисованных кубов. Управление `Begin/EndMode3D` остаётся в `app.os`.

## Этап 1 — сетка и исходная сцена

**Создать:** `Классы/Мир.os`, `tests/testWorld.os` в `examples/minecraft/`.
**Вход:** размеры/ID из ТЗ. **Выход:** полный контракт `Мир`, включая открытые кубы.

- [x] Создать тестовый сценарий с проверками и `ВызватьИсключение` при несовпадении. До реализации класс отсутствовал; после временного маркера импорта тест ожидаемо упал на отсутствующем конструкторе `Мир`.
- [x] Проверить крайние ячейки и раздельное адресование X/Y/Z; соседние координаты не перезаписывают друг друга.
- [x] Проверить чтение за границей → 0, дробные координаты, неверный ID и повторную запись; отказы не меняют версию/мир.
- [x] Реализовать 2048 клеток, формулу индекса и исходную сцену. Проверяются количества 516/16/16/1500 и совпадение двух новых миров.
- [x] Реализовать кэш открытых целых кубов. Проверяются одиночный блок, заполнения 3×3×3, 5×5×5, всего мира и шахматной сетки; повторное чтение возвращает кэш, успешная правка его инвалидирует.
- [x] Проверить `Версия`: успешная запись увеличивает её на один, отказ/повторная запись/чтение оставляют прежней, непустая очистка увеличивает один раз.

Проверка выполнена: `oscript examples/minecraft/tests/testWorld.os` завершился с exit code 0 и строкой `World: OK`; DLL и окно не загружаются.

Опорный код проверки в тесте:

```bsl
Мир = Новый Мир();
Мир.Очистить();
Если Не Мир.УстановитьБлок(1, 2, 3, 1) Или Мир.ПолучитьБлок(1, 2, 3) <> 1 Тогда
    ВызватьИсключение "Запись/чтение ячейки";
КонецЕсли;
Если Мир.УстановитьБлок(-1, 2, 3, 1) Или Мир.ПолучитьБлок(-1, 2, 3) <> 0 Тогда
    ВызватьИсключение "Границы сетки";
КонецЕсли;
```

## Этап 4 — выбор блока лучом

**Создать:** `Модули/ВоксельныйЛуч.os`, `tests/testRaycast.os`.
**Изменить:** `examples/minecraft/app.os` — центральный луч и рамка.
**Вход:** сетка, числовые P/D игрока. **Выход:** контракт попадания с нормалью.

- [x] Создать тесты R01–R23 на пустой мир, ближайший из двух блоков, воду перед землёй, дальность 5 и все шесть нормалей входа. До реализации модульный вызов завершился ошибкой отсутствующего `ВоксельныйЛуч`.
- [x] При нулевом направлении или начальной позиции внутри непустой клетки вернуть промах. Направление нормализовать; дальность измеряется в мировых единицах.
- [x] Отсечь луч по AABB мира `(0,0,0)..(16,8,16)` методом интервалов: нулевая компонента с началом вне соответствующего интервала → промах; иначе на оси нет ограничения. Если вход дальше дальности или выход позади камеры → промах.
- [x] Для начальной клетки внутри интервала применить математический floor. У границы выбрать клетку по знаку луча с малым сдвигом внутрь (epsilon 0.000001), но не прибавлять epsilon к возвращаемой дальности.
- [x] На каждой оси вычислить `step=sign(D)`, `tDelta=abs(1/D)`, `tMax` следующей границы от исходной позиции. При нулевой компоненте — бесконечный логический интервал; деления на ноль нет.
- [x] Переходить по минимальному `tMax`, проверять блок и нормаль `-step` соответствующей оси. При совпадении границ в пределах epsilon шагнуть по всем совпавшим осям; приоритет нормали X, затем Y, затем Z. Не выбирать клетки, которых луч лишь касается ребром/углом.
- [x] Закончить при выходе из AABB, дальности >5 или после 64 переходов (для сетки 16+8+16 этого достаточно). Возвращать расстояние входа в блок, а не расстояние до его центра.
- [x] Проверить отрицательные координаты/направления, луч снаружи мира, параллельный промах, начало на целой границе, точное ребро/угол, расстояние ровно 5 и 5.001.
- [x] Рисовать цель через `НарисоватьКубЛиния` после выхода из shader mode. При промахе рамку не рисовать; ручной осмотр рамки остаётся в чеклисте.

Проверка: `oscript examples/minecraft/tests/testRaycast.os` → `Raycast: OK`, exit 0.

Контрольный пример: единственный блок `(2,2,2)`, начало `(0.5,2.5,2.5)`, направление `(1,0,0)` → попадание `(2,2,2)`, нормаль `(-1,0,0)`, расстояние `1.5`.

## Команды проверки после создания файлов

Все команды из корня репозитория. `oscript` должен быть в PATH; иначе использовать путь к своей установке (в текущем окружении: `/Users/nikita.ivanchenko/.local/share/ovm/current/bin/oscript`). Логические и графические тесты находятся в `examples/minecraft/tests/`.

```bash
dotnet build src/raylibos/raylibos.csproj
oscript examples/minecraft/tests/testWorld.os
oscript examples/minecraft/tests/testPlayer.os
oscript examples/minecraft/tests/testRaycast.os
oscript examples/minecraft/tests/testEditing.os
for script in examples/minecraft/app.os examples/minecraft/Классы/*.os examples/minecraft/Модули/*.os examples/minecraft/tests/*.os; do oscript -check "$script" || exit 1; done
for script in src/test*.os src/waterDemo.os; do oscript -check "$script" || exit 1; done
oscript -check examples/physics/app.os
oscript examples/minecraft/tests/testLighting.os
oscript examples/minecraft/tests/testPerformance.os
oscript examples/minecraft/app.os
```

Логические тесты не подключают DLL, успешны только при exit 0 и строке соответствующего `...: OK`. `-check` проверяет синтаксис, не поведение. GUI-тест требует графического окружения; `app.os` работает до Esc/закрытия окна.

## Уже доступный API и источники

- `src/raylibos/Raylibos.cs`: `НовыйВектор3`, `НоваяКамера3D`, `Начать/ЗакончитьРежим3D`, `НарисоватьКуб`, `НарисоватьКубЛиния`.
- Там же: `КлавишаНажата` означает **IsKeyDown**, `КлавишаНажатаОдин` — IsKeyPressed; `СмещениеМыши`, `КнопкаМышиНажата`, `Включить/ОтключитьКурсор`, `ОкноВФокусе`, размеры экрана, тайминг и HUD.
- Shader: загрузка/готовность/location, значения Int/Float/Vector3, Begin/EndShaderMode и выгрузка уже опубликованы. `ShaderReady` не заменяет проверку location и лога: raylib может вернуть стандартный shader после ошибки GLSL.
- `src/test3d.os`, `src/testShaderMode.os`, `src/waterDemo.os` — существующие примеры 3D/шейдеров/ресурсов. `examples/physics/app.os` — существующий шаблон модулей.
- `GetRayCollisionBox`, генерация мешей и текстурированный `DrawCube` не требуются: луч вычисляется в OneScript, материалы — процедурные, рендер — обычные кубы.
