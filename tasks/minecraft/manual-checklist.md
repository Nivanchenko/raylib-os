# Ручная приёмка voxel-технодемо

**Статус:** этапы 1–6 реализованы, пользовательская документация этапа 7 добавлена. Сборка, логические тесты, синтаксис, оконные shader/performance тесты, отказ GLSL и timed smoke примеров пройдены. Полная ручная проверка управления/фокуса/редактирования, выхода через Esc/кнопку окна и движения водных бликов остаётся открытой. Smoke-результаты сами по себе не закрывают эти пункты.

Запуск примера из корня: `dotnet build src/raylibos/raylibos.csproj`, затем `oscript examples/minecraft/app.os`. Управление: WASD — полёт по горизонтали, Space/Ctrl — вверх/вниз, Tab — захват/освобождение курсора, Esc — выход. Инструкции и критерии приёмки — в [ТЗ](spec.md).

## Сцена и управление

- [ ] **S1 — запуск:** окно 960×540, земля, холм, пруд и два условных дерева; в центре прицел, HUD выбранного типа и FPS. Материалы различимы, нет белого/чёрного экрана и ошибок SHADER.
- [ ] **S2 — конечный мир:** облететь край и посмотреть снизу; видна граница островка. Перезапуск возвращает исходный мир, изменения не сохраняются.
- [ ] **C1 — взгляд:** двигать мышь в обе стороны, вверх и вниз; наклон ограничен, камера не переворачивается. Курсор захвачен, направление не меняется при неподвижной мыши.
- [ ] **C2 — полёт:** W/S, A/D, Пробел/Ctrl двигают в ожидаемую сторону. W двигает по горизонтали даже при взгляде вверх; диагональ не быстрее прямого движения. Проход сквозь блоки разрешён намеренно.
- [ ] **C3 — освобождение курсора:** Tab освобождает мышь и выключает движение/редактирование; следующий Tab возвращает управление без скачка взгляда. Клик для возвращения фокуса не должен удалить блок.
- [ ] **C4 — фокус:** переключиться в другое приложение, отпустить клавиши, вернуться; нет «залипшего» движения и автоматического захвата. Для продолжения нужен Tab.
- [ ] **C5 — resize:** поменять размер окна, свернуть/развернуть; прицел остаётся в центре, HUD читается, окно не зависает. Если экран HiDPI, проверить особенно внимательно соответствие прицела выбранному блоку.

## Прицел и редактирование

- [ ] **I1 — цель:** навести прицел на разные грани земли, воды и древесины; рамка обводит ближайший блок. На небе/при дальности >5 цели нет. Блок за водой не выбирается, пока перед ним есть вода.
- [ ] **I2 — удаление:** короткая ЛКМ удаляет ровно один блок; удержание не удаляет соседние. После удаления видны ранее скрытые блоки, не остаются «дырки в рендере» при наличии блока в сетке.
- [ ] **I3 — установка:** выбрать 1/2/3 и по очереди ставить каждый тип ПКМ на верхнюю, нижнюю и боковые грани; клетка соседняя, не заменяет цель. Удержание не строит автоматически.
- [ ] **I4 — отказы:** попробовать поставить за краем сетки, в занятую клетку и вплотную к глазам; сетка не меняется, HUD показывает отказ. Нет расширения мира и вылета.
- [ ] **I5 — одновременные кнопки:** нажать ЛКМ и ПКМ в одном кадре, насколько возможно; приоритет удаления, не две операции. В `app.os` удаление стоит первой веткой, установка — `ИначеЕсли`; GUI-проверка ещё не проведена.
- [ ] **I6 — внутри блока:** пролететь внутрь земли/дерева/воды; редактирование и рамка выключены до выхода. Отсутствие «подводного» режима и проходимость — ограничения первой версии, не ошибки.
- [ ] **I7 — устойчивость:** выполнить 100 успешных удалений/установок, в том числе возле холма и пруда; кэш обновляется, нет зависания/потери выбранного ID. Вода не растекается после удаления соседней земли.

## Внешний вид

- [x] **V1 — свет:** `testLighting.os` за 3 с обходит три группы образцов; desktop-снимок показывает яркие верхние грани и разные стороны при неизменном мировом направлении света. Теней от дерева на земле не ожидается.
- [ ] **V2 — материалы:** приблизиться к земле и древесине, двигать камеру; зернистость/волокна не «приклеены к экрану» и не ползут по неподвижным блокам.
- [ ] **V3 — вода:** смотреть сверху и сбоку на соседние водные блоки; блики анимируются, цвет непрозрачный, щелей и отдельных несогласованных эффектов на каждой клетке нет. Через воду не должна быть видна земля.
- [ ] **V4 — рамка/HUD:** рамка не мерцает из-за совпадения с гранями, остаётся поверх выбранного куба; HUD вне шейдерного режима и не меняет цвет вместе с материалом.

## Производительность и выход

- [x] **P1 — исходная сцена:** последний запуск `testPerformance.os`, 5 с прогрева + 30 с сбора; среднее 2.6694 мс, p95 3.9209 мс, 374.62 FPS, 526 кубов, 0 кадров >100 мс; render size 1920×1080.
- [x] **P2 — после редактирования:** тот же тест после ровно 100 успешных изменений; среднее 2.5176 мс, p95 4.1051 мс, 397.20 FPS, 540 кубов, 0 кадров >100 мс. Это автоматический профиль, не ручная проверка I7.
- [x] **P3 — стресс-профиль:** шахматная сетка, 1024 реально рисуемых куба; среднее 4.2219 мс, p95 5.0218 мс, 236.86 FPS, 0 кадров >100 мс, без вылета. Диагностический результат не является гарантией 60 FPS.
- [ ] **E1 — выход:** отдельно закрыть через Esc и кнопку окна; процесс завершается, курсор доступен другим приложениям, shader выгружен до закрытия графического контекста. Затем снова запустить демо.
- [ ] **E2 — отказ шейдера:** на временной копии GLSL вне tracked-ассетов проверить неправильный путь и синтаксическую ошибку. Получить понятный отказ, а не молчаливый белый мир; окно закрывается, курсор не остаётся захваченным. Не менять/не терять пользовательские shader-файлы ради проверки.
- [ ] **E3 — регрессия:** запустить существующее `oscript src/waterDemo.os` и `oscript src/test3d.os`; их поведение не изменилось. В примере `test3d.os` есть явная пауза 500 мс — низкий FPS там не считать регрессией нового рендера.

## Оконные и интеграционные проверки

- Временная автозакрывающаяся копия `app.os`, запущенная из корня репозитория, завершилась с exit 0: окно 960×540 и пользовательский GLSL shader созданы, цикл отрисовки отработал, shader и окно штатно закрыты.
- Проверка отказа: запуск временной копии из каталога без `resources/` вернул exit 1, записал предупреждения FILEIO для shader и завершился строкой `Window closed successfully`; ошибка передана вызывающему коду.
- Ручной ввод не проверен: отправка Esc через macOS System Events запрещена системой (ошибка 1002). Поэтому C1–C5 и E1 остаются незакрыты; основную сцену игры вручную не осматривали (отдельно осмотрен снимок материал-теста этапа 6).
- `testRaycast.os` вывел `Raycast: OK` для R01–R23. Временная автозакрывающаяся копия `app.os` также завершилась с exit 0 после трёх секунд кадрового цикла с подключённым DDA; shader скомпилировался и окно закрылось. Проверка выбора/видимости рамки человеком не проводилась, I1 и V4 остаются незакрыты.
- `testEditing.os` вывел `Editing: OK` для E01–E13. Smoke-копия приложения с вводом редактирования завершилась с exit 0; ручные проверки удаления/установки, приоритета одновременных кнопок и HUD не выполнялись, I2–I5 остаются незакрыты.
- `testLighting.os` вывел `Lighting: OK`; оба GLSL-файла скомпилированы. Тест показывает по 3×3×3 блока каждой группы, подтверждает 78 открытых блоков и отсечение далёких блоков; desktop-снимок проверен на наличие материалов, освещения и непрозрачной воды. Ручная проверка V2/V3 с перемещением камеры и динамикой бликов остаётся открытой.
- `testPerformance.os` вывел `Performance profiles: DONE`; при повторе для этапа 7 фактическое число кубов подтверждено как 526/540/1024 на всех кадрах сбора, 0 кадров >100 мс. Значения и среда приведены в таблице выше; тест печатает только три итоговые строки.
- Timed smoke-копии `app.os`, `src/waterDemo.os` и `src/test3d.os` завершились с exit 0; Minecraft-приложение выгрузило shader и закрыло окно, обе старые демо тоже закрылись. Временные варианты с отсутствующим shader и синтаксической ошибкой GLSL завершились с exit 1 после закрытия окна. Курсор глазами и визуальное поведение старых демо не проверялись; E1–E3 поэтому оставлены незакрыты.

Команда повторного замера: `oscript examples/minecraft/tests/testPerformance.os`. GPU и фактический render size подтверждены raylib-логом; FPS не ограничивался (`SetTargetFPS(0)`). И базовые, и последние профили превысили ориентир 30 FPS / p95 ≤50 мс на этой машине; результат не переносится на другие GPU.
