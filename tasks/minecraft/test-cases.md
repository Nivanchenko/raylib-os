# Детерминированные тестовые случаи

Сценарии ниже — данные для будущих тестов, а не результаты выполненных Minecraft-тестов. Все случаи независимы: создавать новый `Мир`, очищать его, если указано, и новый `Игрок`. Точность сравнения дробных результатов — 0.000001; числовые ID/координаты/нормали сравнивать точно.

## Общий шаблон headless-теста

Начало каждого `examples/minecraft/tests/test*.os`, кроме GUI-тестов:

```bsl
#Использовать ".."

Процедура Проверить(Условие, Сообщение)
    Если Не Условие Тогда
        ВызватьИсключение Сообщение;
    КонецЕсли;
КонецПроцедуры

Процедура ПроверитьЧисло(Факт, Ожидание, Сообщение)
    Проверить(Макс(Факт - Ожидание, Ожидание - Факт) <= 0.000001, Сообщение);
КонецПроцедуры
```

Внизу сценария `Сообщить("World: OK")` / `Player: OK` / `Raycast: OK` / `Editing: OK` соответственно. Печатать только после всех проверок. Не использовать GUI или `ПодключитьВнешнююКомпоненту`.

## E: testEditing.os

Начало каждого случая: очищенный мир с землёй B=(2,2,2), `Выбор` из луча R01. Для установки сосед Q=(1,2,2); позиция камеры по умолчанию `(0.5,2.5,2.5)`, достаточно далеко от Q.

| ID | Действие | Проверить |
|---|---|---|
| E01 | Удалить B | ID B=0, `Изменено=Истина`, `Причина="ok"`, версия +1 |
| E02 | Удалить промах | Без записи/изменения версии, `no-hit` |
| E03 | После удаления снова передать старый Выбор | `no-hit`, версия не меняется |
| E04 | Установить каждый ID 1/2/3 в свежем случае | ID Q правильный, B сохранён, версия +1, `ok` |
| E05 | До установки заполнить Q древесиной | ID Q=3 сохранён, `occupied`, версия без изменения |
| E06 | ID=0/4/1.5 | `invalid-type`, записи нет |
| E07 | Позиция камеры=(1.5,2.5,2.5) | `near-camera`, записи нет |
| E08 | Позиция камеры=(0.8,2.5,2.5) | Куб безопасности касается Q; установка разрешена |
| E09 | Позиция камеры=(0.81,2.5,2.5) | Есть строгое пересечение Q; `near-camera` |
| E10 | Цель `(0,2,2)`, нормаль (-1,0,0) | Q вне сетки, `bounds` |
| E11 | Нормаль (0,0,0) или (1,1,0) | `invalid-hit`, записи нет |
| E12 | Выбор с расстоянием 5.001 или нецелой координатой цели | `no-hit`, записи нет |
| E13 | Удалить центр 5³, как W12 | Кэш 104 вместо 98, рендер узнаёт об изменении по версии |

Для E10 сначала очистить мир и реально поставить указанную цель; не передавать фиктивное попадание в пустую клетку. Во всех отказах дополнительно проверять **весь массив ID** или контрольные клетки и версию, не только строку причины.

## G/P: GUI и измерения

Автоматизируются лишь загрузка shader/наличие location/выход. Свет, фокус, прицел и материалы принимаются по [ручному чеклисту](manual-checklist.md).

- `testLighting.os`: окно 3 секунды, все три ID рядом, location `uTime/uMaterial/uLightDirection >=0`, собственный shader освобождён, exit 0 и `Lighting: OK`. Ошибка GLSL — ненулевой exit и понятное сообщение.
- `testPerformance.os`: три профиля из раздела 9 `implementation-notes.md`, по 5+30 секунд. В стресс-профиле сетка содержит 1024 открытых куба; фактическое число нарисованных зависит от отсечения 24 единицы и положения камеры.
- Проверка формулы метрик на данных `[0.01,0.03]`: среднее 20 мс, FPS=50, не среднее `(100+33.33)/2`.
- Проверка p95 на 20 значениях 1..20 мс: 19 мс (nearest-rank), на четырёх 10/20/30/40 мс: 40 мс.
- До получения реальных результатов не отмечать производительность успешной и не публиковать замеры как выполненные.
