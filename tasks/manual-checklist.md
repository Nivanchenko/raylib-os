# Чеклист ручной проверки raylibos

Этот файл — **задания для человека**, не отчёт о пройденных тестах. Отмечайте `[x]` после проверки; если что-то не работает, напишите номер пункта, фактическое поведение, ОС, команду запуска и текст ошибки из терминала. Пункты с устройствами выполняйте только при их наличии.

## Подготовка

- [ ] Из корня репозитория выполнена сборка: `dotnet build src/raylibos/raylibos.csproj`. Примеры ищут `src/raylibos/bin/Debug/net6.0/raylibos.dll`; после новой сборки запускайте из **корня** репозитория, иначе пути `resources/...` могут не найтись.
- [ ] `oscript` доступен в `PATH`. Если нет — заменяйте `oscript` в командах на путь к своей установке (у автора проекта: `/Users/nikita.ivanchenko/.local/share/ovm/current/bin/oscript`). Нужны рабочие GUI и аудиоустройство для соответствующих пунктов.

## В первую очередь: не проверяется синтаксисом и сборкой

- [ ] **D1 — drag-and-drop:** `oscript src/testDropFiles.os`. За первые 10 секунд перетащите из Finder/Explorer один файл, затем несколько файлов сразу; по возможности файл с кириллицей в имени. Ожидается путь в окне и по строке `Перетащен файл: ...` в терминале на каждый файл, без ошибки/зависания. Проверка пустого списка без перетаскивания уже встроена в пример; **получение непустого списка ранее вручную не подтверждалось**. Для повторения откройте пример снова.
- [ ] **A1 — слышимость:** `oscript src/testAudio.os`. Сразу после открытия слышен короткий тон (~0,2 с); за 3 секунды нажмите `Пробел` несколько раз — тон слышен при каждом нажатии, без треска. Окно само закрывается; терминал не содержит ошибок; устройство корректно освобождено. Успешный лог об инициализации аудио **не доказывает**, что звук слышен.
- [ ] **W1 — полноэкранный режим:** `oscript src/testWindowState.os`. Скрипт сразу переключает окно в полноэкранный режим; коротко нажмите `F` для возврата в окно, измените размер мышью и проверьте надписи `Fullscreen` и `GetScreenWidth/Height`/`GetRenderWidth/Height`. Нажмите `F` повторно, затем закройте окно. Если `F` переключает многократно за одно удержание, или resize не работает — отметьте отдельно: в текущем демо `F` проверяется как удержание (`КлавишаНажата`), флаг resizable задаётся **после** создания окна, поведение может зависеть от платформы.
- [ ] **I1 — клавиатура/мышь:** `oscript src/testKeyDown.os`: удерживайте стрелки — круг перемещается; короткое нажатие и отпускание `→` дают надписи `RIGHT pressed` и `RIGHT released` (один кадр, могут быстро исчезнуть). Затем `oscript src/testMouse.os`: переместите мышь — круг следует за ней; левая кнопка меняет цвет, поля `down/released/up` соответствуют действиям; коротко нажмите `H` — курсор скрывается, второе нажатие показывает. Если `H` мерцает/переключается при удержании — отметьте: демо тоже использует проверку удержания.
- [ ] **C1 — 2D-камера:** `oscript src/test2dcamera.os`. Стрелки `←/→` двигают красного игрока, камера следует за ним; колесо увеличивает/уменьшает сцену, `A/S` поворачивают, `R` сбрасывает угол и масштаб. Закройте окно. При обратном направлении колеса или неожиданных прыжках камеры сообщите платформу и конкретное действие.

## Визуальная отрисовка и ресурсы

- [ ] **G1 — render texture:** `oscript src/testRenderTexture.os` (закрывается через 3 с). Видна красная окружность на белом фоне, сцена занимает окно; нет пустой/чёрной текстуры или исключений. **Вертикальную ориентацию этим примером установить нельзя:** окружность симметрична; если нужна строгая проверка Y-flip, сообщите — добавим асимметричный маркер в демо.
- [ ] **G2 — шейдер:** `oscript src/testShaderMode.os` (3 с). Есть красная окружность, эффект не превращает её в пустую/чёрную область; в терминале нет ошибок компиляции GLSL. Установка uniform проверена вызовами, но видимый результат и устройства GPU отличаются — сообщайте цвет/артефакты и сообщения `SHADER`.
- [ ] **G3 — прозрачность и центрирование:** `oscript src/testColorUtils.os` (3 с): поверх серых прямоугольников красный и синий становятся всё менее прозрачными; `oscript src/testMeasureText.os` (2 с): надпись расположена по центру относительно вертикальной линии. Если фон не просвечивает/центр уходит в сторону — сообщите.
- [ ] **G4 — коллизии:** `oscript src/testCollisions.os` (3 с): переместите указатель к неподвижному прямоугольнику и кругу — при пересечении фигуры меняют цвет на красный, иначе синие; положительные/отрицательные логические проверки вызываются до отрисовки. `oscript src/testCollisions3D.os` (2 с): видны боксы и сферы, без ошибок (логические проверки тоже встроены).
- [ ] **G5 — текстуры/3D:** `oscript src/testTextureGen.os`: нажмите левую кнопку мыши 9 раз — по кругу переключаются вертикальный/горизонтальный/диагональный градиенты, радиальный/квадратный градиенты, шахматный узор и три вида шума. Затем `oscript src/testModelTexture.os`: замок с текстурой и зелёным ограничивающим боксом, камера плавно вращается; `oscript src/test3dPrimitives.os` (2 с): видны сфера и линия. Для первых двух примеров закройте окно сами; смотрите логи загрузки `resources/...` и освобождения GPU-ресурсов.

## Только при наличии оборудования

- [ ] **У1 — геймпад:** подключите физический геймпад, запустите `oscript src/testInput.os` (5 с). Скрипт опрашивает доступность, оси и кнопки, но **не показывает их значения на экране**; отсутствие ошибки подтверждает лишь безопасность вызовов. Для проверки нажатий/осей попросите добавить отдельное наглядное демо, указав модель контроллера и ОС.
- [ ] **У2 — тач/жесты:** при наличии сенсорного экрана запустите `oscript src/testInput.os` (5 с), попробуйте касание, удержание, перетаскивание и pinch. Текущий скрипт выводит количество касаний/код жеста, но для точной проверки идентификаторов и векторов понадобится специальное демо. Если устройства нет, оставьте пункт пустым и напишите «нет устройства».
- [ ] **У3 — VR / ручной кадр:** демо и обёрток ещё нет; это будущая [task13.md](task13.md), сейчас запускать нечего. Укажите доступное VR-оборудование/платформу, если направление нужно.

## Как прислать результат

Скопируйте только проверенные пункты, например: `D1 — ошибка: при двух файлах выводится один; macOS ..., oscript ..., лог: ...`. Для ошибки приложите команду запуска, первые строки исключения/лога, что именно нажали или перетащили, ожидаемое и фактическое поведение. Для визуального дефекта полезен скриншот; для проблемы с аудио — устройство вывода и слышен ли звук в других приложениях. Не отмечайте непроверенные пункты как успешные.
